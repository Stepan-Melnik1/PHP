# Лабораторная работа №5. Объектно-ориентированное программирование в PHP

Приложение для управления банковскими транзакциями, написанное на PHP с использованием ООП, строгой типизации и интерфейсов.

## Цель работы

Освоить основы объектно-ориентированного программирования в PHP на практике: научиться создавать собственные классы, использовать инкапсуляцию для защиты данных, разделять ответственность между классами и применять интерфейсы для построения гибкой архитектуры приложения.

## Возможности приложения

- хранение банковских транзакций;
- добавление и удаление транзакций;
- поиск транзакции по идентификатору;
- сортировка транзакций по дате и по сумме;
- вычисления над коллекцией (общая сумма, сумма за период, количество по получателю);
- вывод данных в виде HTML-таблицы.

## Архитектура

Все классы находятся в одном файле `index.php`. В начале файла включена строгая типизация: `declare(strict_types=1);`.

| Класс / интерфейс | Ответственность |
|---|---|
| `Transaction` | Описывает одну транзакцию: `id`, `date`, `amount`, `description`, `merchant`, `category`. Все свойства приватные, значения задаются через конструктор, доступ через геттеры. Метод `getDaysSinceTransaction()` возвращает количество дней с момента транзакции. |
| `TransactionStorageInterface` | Контракт для любого хранилища транзакций: `addTransaction`, `removeTransactionById`, `getAllTransactions`, `findById`. |
| `TransactionRepository` | Реализует `TransactionStorageInterface`. Хранит транзакции в приватном массиве и отвечает только за хранение и базовые операции доступа. |
| `TransactionManager` | Бизнес-логика: расчёты и сортировка. Сам транзакции не хранит, получает хранилище через конструктор (зависимость от интерфейса, а не от конкретного класса). |
| `TransactionTableRenderer` | `final`-класс, который формирует HTML-таблицу из массива транзакций. |

### Методы `TransactionManager`

- `calculateTotalAmount(): float` — общая сумма всех транзакций;
- `calculateTotalAmountByDateRange(string $startDate, string $endDate): float` — сумма за период (границы включаются);
- `countTransactionsByMerchant(string $merchant): int` — количество транзакций по получателю;
- `sortTransactionsByDate(): array` — сортировка по дате (от старых к новым);
- `sortTransactionsByAmountDesc(): array` — сортировка по сумме по убыванию.

### Таблица на выходе

Столбцы: ID, дата, сумма, описание, получатель, категория получателя, количество дней с момента транзакции.

Категория получателя хранится в `Transaction` как необязательный параметр конструктора со значением по умолчанию `"Прочее"`.

## Начальные данные

В приложение добавлено 10 транзакций с разными датами, суммами, описаниями и получателями. В основном коде выполняется только вызов `render()` и вывод результата через `echo`.

## Запуск

Требуется PHP 8.0 или выше (используется constructor promotion).

```bash
php -S localhost:8000
```

После этого откройте в браузере `http://localhost:8000`.

Весь код задокументирован по стандарту PHPDoc: для каждого класса, свойства и метода описаны назначение, входные параметры и возвращаемое значение.

## Контрольные вопросы

**1. Зачем нужна строгая типизация в PHP и как она помогает при разработке?**

По умолчанию PHP молча приводит типы: если функция ожидает `int`, а передана строка `"5"`, она будет преобразована автоматически. Из-за этого ошибки могут проявляться далеко от места, где они были допущены. С `declare(strict_types=1)` PHP выбрасывает `TypeError` сразу при передаче значения неверного типа. Код становится предсказуемее, а типы в сигнатурах служат дополнительной документацией.

**2. Что такое класс в ООП и какие основные компоненты класса вы знаете?**

Класс — это шаблон, по которому создаются объекты. Он объединяет данные и поведение. Основные компоненты: свойства (хранят состояние), методы (описывают поведение), конструктор `__construct` (задаёт начальные значения), модификаторы доступа `public`, `private`, `protected`, а также константы и статические члены.

**3. Объясните, что такое полиморфизм и как он может быть реализован в PHP.**

Полиморфизм — это возможность работать с объектами разных классов через общий интерфейс, при этом каждый объект ведёт себя по-своему. В PHP он реализуется через интерфейсы, наследование с переопределением методов и абстрактные классы. В данной работе `TransactionManager` принимает `TransactionStorageInterface`, поэтому ему всё равно, где именно хранятся транзакции: в массиве, файле или базе данных.

**4. Что такое интерфейс в PHP и как он отличается от абстрактного класса?**

Интерфейс — это контракт: он содержит только сигнатуры методов без реализации и без состояния. Класс может реализовывать несколько интерфейсов. Абстрактный класс может содержать как абстрактные методы, так и готовую реализацию, а также свойства и конструктор, но наследоваться можно только от одного класса. Интерфейс отвечает на вопрос «что объект умеет», абстрактный класс — «что общего у родственных объектов».

**5. Какие преимущества дает использование интерфейсов при проектировании архитектуры приложения? Объясните на примере данной лабораторной работы.**

`TransactionManager` зависит не от конкретного класса `TransactionRepository`, а от интерфейса `TransactionStorageInterface`. Это даёт:

- **гибкость и заменяемость** — можно написать хранилище на основе файла или базы данных, и менеджер будет работать с ним без изменений;
- **слабую связанность** — изменения в одном классе не ломают другие;
- **удобство тестирования** — вместо реального хранилища можно подставить простую заглушку;
- **чёткий контракт** — сразу видно, что должно уметь любое хранилище транзакций.
